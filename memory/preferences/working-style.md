# Ryan's Working Preferences

## Communication Style

- **Direct and clear**: No corporate speak, get to the point
- **Evidence-based**: Prefer data and examples over opinions
- **Written over verbal**: Document decisions and discussions
- **Async-first**: Written updates, not status meetings

## Decision Making

- **Write it down**: Even obvious decisions get documented
- **Show your work**: Include rationale and trade-offs
- **Make it reversible**: Prefer decisions that can be undone
- **Explicit ownership**: Clear who decides and who executes

## Prioritization

- **Customer impact first**: Focus on end-to-end journey
- **Signal quality matters**: Good data beats loud opinions
- **Make trade-offs explicit**: What are we not doing and why?
- **Capacity is real**: Don't over-commit

## Product Development

- **Clarify boundaries early**: Use DDD to define ownership
- **Ship to learn**: Prefer small, reversible releases
- **Measure what matters**: Define success metrics before shipping
- **Plan for failure**: Know how to detect and recover

## AI in Production

- **Guardrails are non-negotiable**: Handoff, refusal, confidence
- **Observability from day one**: Metrics, logs, alerts
- **Human override is a feature**: Not a failure
- **Rollback plan required**: Know how to turn it off

## Meetings and Collaboration

- **Meetings for coordination**: Not for discovery or status
- **Agendas required**: Know what we're deciding
- **Action items with owners**: Clear next steps
- **Follow up in writing**: Summarize and document

## Documentation

- **Runbooks for repeatable work**: Don't rely on memory
- **Keep it current**: Update docs when things change
- **Link related content**: Make it easy to find context
- **Templates for common tasks**: Reduce cognitive load

## Feedback and Learning

- **Blameless postmortems**: Focus on systems, not people
- **Capture in the flow**: Don't wait for perfect documentation
- **Update based on usage**: Knowledge evolves
- **Retire outdated content**: Don't let docs rot

## Tools and Workflows

- **Prefer existing tools**: Don't build what you can buy
- **Automate repeatable tasks**: Save time for thinking
- **Version control everything**: Code, docs, decisions
- **Make it easy to contribute**: Low friction for updates
