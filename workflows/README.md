# Workflows

Guided workflows for common product management tasks.

## Available Workflows

### Product Development

- `new-feature.md` - End-to-end flow for new feature development
- `feature-validation.md` - Validate feature ideas before building
- `release-planning.md` - Plan and execute product releases

### Customer Research

- `customer-discovery.md` - Discover and validate customer problems
- `user-interview.md` - Conduct effective user interviews
- `signal-triage.md` - Triage and act on customer signals

### AI Features

- `ai-feature-launch.md` - Launch AI features safely in production
- `ai-monitoring.md` - Monitor and maintain AI systems
- `ai-incident-response.md` - Respond to AI system incidents

### Incident Response

- `incident-triage.md` - Initial incident response and triage
- `postmortem.md` - Conduct blameless postmortems
- `action-tracking.md` - Track and close postmortem action items

### Decision Making

- `prioritization.md` - Prioritize features and initiatives
- `build-vs-buy.md` - Decide whether to build or buy
- `technical-decision.md` - Make technical architecture decisions

## Workflow Format

Each workflow follows this structure:

```markdown
---
description: [Short description of what this workflow does]
---

# Workflow Name

## When to Use
[Situations where this workflow applies]

## Prerequisites
[What you need before starting]

## Steps
1. [First step]
2. [Second step]
...

## Outputs
[What you'll have when done]

## Next Steps
[What typically comes after this workflow]
```

## Using Workflows

1. Find the relevant workflow for your task
2. Follow the steps in order
3. Use suggested slash commands at each step
4. Document outputs in the specified locations
5. Link to related workflows for next steps

## Creating New Workflows

When you find yourself doing the same sequence of tasks:

1. Document the steps
2. Add decision points and branches
3. Include relevant commands and templates
4. Link to related workflows
5. Save in this directory
